# ToDo API

Учебный REST API на FastAPI для задач и матрицы Эйзенхауэра. Маршруты используют локальный PostgreSQL. Каждый пользователь управляет своими задачами; администратор видит и изменяет задачи всех пользователей. Приложение вычисляет срочность и квадрант по сроку выполнения.

## Запуск

1. Запустите PostgreSQL и создайте базу `todo_api`.
2. Создайте `.env` в корне проекта:

```text
DATABASE_URL=postgresql+asyncpg://USER:PASSWORD@127.0.0.1:8000/todo_api
SECRET_KEY=RANDOM_HEX_STRING
```

Секретный ключ можно создать командой `openssl rand -hex 32`. Файл `.env` исключён из Git.

3. Установите зависимости и запустите сервер:

```bash
python -m venv venv
source venv/bin/activate
pip install -r requirements.txt
uvicorn main:app --reload --port 8001
```

Swagger: http://127.0.0.1:8001/docs. Проверка базы: http://127.0.0.1:8001/api/v2/health.

При старте приложение создаёт отсутствующие таблицы и добавляет столбцы `deadline_at` и `user_id` в существующую таблицу задач. Старые задачи сохраняются. До назначения владельца старую задачу видит только администратор. Срок передаётся как ISO 8601 с часовым поясом, например `2026-11-22T12:00:00+03:00`. Если часовой пояс не указан, дата трактуется как UTC.

## Вход и роли

1. Создайте пользователя через `POST /api/v2/auth/register` с полями `nickname`, `email`, `password`.
2. В Swagger нажмите **Authorize** и в поле `username` введите email, а в поле `password` — пароль. Вход также доступен через `POST /api/v2/auth/login`.
3. После входа используйте маршруты задач и статистики. Токен действует 24 часа.

Регистрация всегда создаёт роль `user`. Для учебной проверки администратор назначается в локальной базе командой `UPDATE users SET role = 'admin' WHERE email = '...';`. Роль берётся из базы при каждом запросе. `GET /api/v2/auth/me` показывает текущего пользователя. `PATCH /api/v2/auth/change-password` принимает `old_password` и `new_password`. `GET /api/v2/admin/users` доступен только администратору и показывает количество задач каждого пользователя.

## Маршруты

| Метод | Путь | Действие |
| --- | --- | --- |
| GET | `/api/v2/tasks` | Список задач |
| POST | `/api/v2/tasks` | Создать задачу |
| GET | `/api/v2/tasks/{task_id}` | Задача по ID |
| PUT | `/api/v2/tasks/{task_id}` | Изменить задачу |
| PATCH | `/api/v2/tasks/{task_id}/complete` | Завершить задачу |
| DELETE | `/api/v2/tasks/{task_id}` | Удалить задачу |
| GET | `/api/v2/tasks/search?q=...` | Поиск |
| GET | `/api/v2/tasks/status/{status}` | Фильтр по статусу |
| GET | `/api/v2/tasks/quadrant/{quadrant}` | Фильтр по квадранту |
| GET | `/api/v2/tasks/today` | Незавершённые задачи со сроком сегодня по UTC |
| GET | `/api/v2/stats` | Общая статистика |
| GET | `/api/v2/stats/timing` | Статистика сроков |
| GET | `/api/v2/health` | Проверка БД |
| POST | `/api/v2/auth/register` | Регистрация |
| POST | `/api/v2/auth/login` | Вход и выдача токена |
| GET | `/api/v2/auth/me` | Текущий пользователь |
| PATCH | `/api/v2/auth/change-password` | Смена пароля |
| GET | `/api/v2/admin/users` | Пользователи и число задач для администратора |

Пример создания задачи:

```json
{
  "title": "Подготовить отчёт",
  "description": "Практика 5",
  "is_important": true,
  "deadline_at": "2026-11-22T12:00:00+03:00"
}
```

Срок не обязателен. Срочность включается, когда до срока осталось не больше 72 часов. Планировщик пересчитывает срочность и квадрант незавершённых задач каждый день в 09:00 по Москве. Поле `days_until_deadline` показывает разницу календарных дат по UTC; отрицательное число означает прошедшую дату. Задачи без срока не учитываются в статистике сроков.

## Проверки

```bash
python test_connection.py
python -m unittest discover -s tests -v
```

Тесты используют локальную базу, создают временных пользователей и задачи и удаляют их после проверки. Не запускайте несколько копий приложения одновременно с одной базой, иначе каждый процесс запустит свой планировщик.
